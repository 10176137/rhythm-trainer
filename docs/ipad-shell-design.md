# iPad React 容器与电脑后端

目标：在 iPad 安装可启动的应用，复用现有 React 乐谱和练习界面；电脑继续连接电子琴并运行 Node 与 Rust。电脑必须保持运行，设备需局域网互通。

## 方案

采用 Capacitor iOS 容器，将 Vite 构建产物打包进应用，不将开发服务器 URL 固定在容器配置中。首次启动展示简洁的电脑服务地址输入与连接按钮；成功后进入现有练习页。地址保存在本机，可在设置中修改。普通网页继续沿用同源访问。

抽取统一的后端地址解析，覆盖所有 REST repository、engineBridge 和 deviceBridge；由 HTTP/HTTPS 地址对应生成 WS/WSS 地址，校验协议和非法输入，避免仅修改评分连接而遗漏训练、设备或报告请求。

电脑提供局域网可访问的服务入口，处理容器来源的跨域请求及预检。iOS 配置局域网用途说明及必要的本地网络传输权限，不开放任意远程网页导航。原生层不接入 MIDI，也不迁移生成器、评分和数据库。

## 使用状态

连接前显示连接页，失败提供可理解的错误与重试；设置地址前不发业务请求。失联时明确显示离线，禁止重复开始。重新连接后先核对服务与练习状态，不盲目重放开始、结束等操作，不承诺自动续接尚无恢复协议的会话。应用从后台返回时重新检查连接。

评分仍以电脑的 MIDI 采集时间和 Rust 内核为依据。iPad 的接收时间不作为演奏时间。现有时钟同步与音频路径需实测，避免将局域网部署等同于已经完成音画延迟校准。

## 验证与交付

验证地址解析、REST/WS 一致性、网页同源兼容、错误地址及断线重连行为；运行项目要求的相关测试、完整测试、teaching 测试及构建。检查 iOS 工程可用性；安装到实体 iPad 的签名与运行由本机 Xcode 和设备条件决定，未实测部分明确列出。

交付包含容器工程、电脑启动说明和 iPad 连接说明。首版采用手动填写电脑地址，不增加账号系统、云服务或设备自动发现。
