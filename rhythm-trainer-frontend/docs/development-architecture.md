# 让功能在正确的模块中增长

先确定职责和状态归属，再画页面。文件行数是检查信号，不能代替模块设计。

| 模块 | 唯一职责 | 输入与输出 |
| --- | --- | --- |
| App / 路由 | 组装页面，连接现有功能，发起导航 | 路由、模块状态、回调 |
| PerformanceToolbar | 演奏配置与设备入口 | 当前配置 → 用户修改命令 |
| PracticeSessionControls | 所有计时练习共用的会话按钮 | 会话状态 → 开始、暂停、继续、结束、重置命令 |
| TrainingRoundPanel | 专项结果展示 | 已保存的后端报告 → 页面 |
| usePracticeSession / EngineBridge | 前端会话生命周期与协议 | 用户命令、后端事件 → UI 状态 |
| server/session-clock | 以捕获时间确定首键起点及后续时间 | 原始 MIDI、后端首音目标 → 统一会话时间 |
| server/plan-note-range | 校验 A/B 边界，保留和裁剪延音关系 | 完整语义文档、端点 ID → 选段文档 |
| server/planner-service / Rust | 计划、评分、版本和指纹校验 | 后端校验的输入 → 权威计划与报告 |

依赖方向：页面 → 功能控制器 → 客户端接口 → Node → Rust。浏览器不导入 server 运行时代码；Node 业务模块不导入 React 或谱面渲染器。组件不能再创建一套出题、选段或评分规则。

同一数据只有一个所有者。配置草稿只能在明确的编辑流程中存在；确认后使用同一冻结快照创建计划和 Take。各模式可以有不同内容，但不能各自实现一套暂停、保存或断连逻辑。

首键启动不重写 Rust 目标和计划指纹：后端把首个有效按键的捕获时间映射到首音目标时间，随后接受按下、松开、踏板事件。前端根据后端发出的起点显示和播放，网络到达延迟不参与成绩计算。

选段使用完整语义源及音符 ID。后端按起音窗口保留和弦成员；边界截到延音时只保留选区内的延音链，选区内首音成为可重新落键的起音。单独保留一个延音成员时按普通音处理。原始谱源不修改，选段结果继续通过 Rust 文档和指纹校验。

现有 App 仍承载历史流程，按所改功能逐步迁移。不要为了减少行数一次性重写整套计划、Take 或报告链路；也不要把一段复杂业务搬进名为 utils 的文件后宣称完成分层。

## 可以直接给 AI 的要求

读谱演奏进入页面即自动准备计划，手动开始按钮隐藏；待弹阶段静音且不倒数。`ArmedTakeClock` 只接受验证计划首个目标组的音高，首组和弦任一成员可启动，启动前错音、松键、踏板不进入本轮评分；首个正确音本身必须保留为首目标输入。Follow 的待弹门禁同样在 Node，忽略的输入返回 `waiting` 提示且不进入重放证据。前端只据服务端事件显示待弹/计时。

与读谱不同，固定判定线、节奏识谱和专项训练不在进入页面、换曲或修改配置时自动开始：用户点击开始后才倒数并按时间推进，不等首键；自动开始与自动结束是两条独立策略（`sessionStartPolicy`）。判定线开始后的暂停／继续只顺延会话时钟并复用同一 Take，重复命令不累计暂停、不新建 Take。

待弹时修改配置、选择音符、换页、切模式和试听，经 `useScorePick` 排队结束旧 Take 后执行；不能解锁按钮后直接修改冻结计划。自动准备须等待规划器权威、手别映射与配置提交完成。试听结束恢复待弹，不创建并行 Take。

从未触发正确首音的待弹记录标为 `lifecycle.standbyOnly`，保留审计文件但不列入演奏记录和能力档案；修改待弹配置或离页不能制造虚假的零分练习。

普通曲目（含单手）和循环单轮的固定时间演奏由 `server/song-completion.mjs` 根据验证过的目标时值与谱面末尾休止计算结束边界，加入 250 ms 收尾缓冲；暂停区间顺延边界。服务端 tick 到达终点后走既有 `finishSession` 和持久化链，只结算一次。前端不按命中目标数量猜测结束，也不在最后一个 Note On 时截断长音。识谱及专项训练保留各自的结束策略；Follow 继续由 Rust 最后一组完成事件触发保存。

演奏的结束归位由 `useRoundReturn` 统一控制：每个结束的 Take 只清理一次高亮、计时和声音，并返回本轮起点。自动完成的整曲和循环只在报告保存成功后创建下一轮；固定时间下一轮为首键启动，跟手下一轮直接等待目标。手动结束、重选音符、离开页面及不可信中断不能触发自动续轮。首次完成时冻结是否续轮的意图，不能因下一次手动点击开始清除了停止标志而重复启动旧轮次。

记录详情的逐音符复盘通过 `GET /api/takes/:id/note-review` 读取。`server/note-review.mjs` 把保存的 Rust 起音、音高、时值证据转换为展示 DTO，不改写成绩或 Take。起音容差只识别已验证的版本；未知版本保留数值并标为未完整判定。时值需由按键生命周期与唯一 assessment 精确对应，且目标时值一致，不能把同一拍音符组的时值判定套给不同长度的音符。Follow 保留分组间隔语义，不冒充固定时间或逐音时值判定。

`NoteReviewPanel` 只负责加载、筛选、翻页、选择和谱面定位。使用历史内容寻址快照并核对语义指纹；不能用曲库中后来替换的乐谱重写历史定位。运行时 ID 只允许精确 ID 或唯一源 ID 后缀定位，不按相同音高或条目索引猜测。重复出现的源音符在谱面保留较严重的颜色，各次明细仍独立存在；无法定位的多弹音保留在列表。

谱面定位与试听复用 `scoreSelection` 请求描述：无选区从头播放，单独起点播放到曲尾，循环使用 A/B 范围。裁剪和延音关系仍由 Node 处理，时序由 Rust 生成。`useScoreAudition` 只拥有音频播放状态，不创建 Take；`useScorePick` 在按下时停声，等待旧 Take 保存后才应用新位置。`useElapsedClock` 只显示本轮时长，与不可变的评分时间原点分离，首键等待不累计，重选和重练清零。

> 开发前，先列出功能所属模块、每份状态的唯一所有者、前后端接口和依赖方向。App 只做页面组装；组件只负责展示和输入；功能控制器处理请求生命周期；Node 负责业务校验、出题、选段、诊断和持久化；Rust 负责计时计划与最终评分。所有计时练习复用同一套会话控制。优先扩展现有模块，不在页面复制业务规则。文件变长时按职责拆分，不按行数切分。实现后验证成功、失败、取消、断连和重复请求，并说明测试证据与尚未验证的实机行为。
