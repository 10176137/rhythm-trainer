# 每行四小节的显示网格

谱面阅读与演奏的多行谱面共用 `components/osmdEngraving.ts`：每行四个等宽位置，首列的谱号、调号、拍号，以及尾部终止线，都包含在所在小节宽度内。最后一行不足四小节时以空白五线谱补齐，不拉宽剩余小节。密集音型所需宽度不足时扩大谱面画布，保留滚动，而不压缩音符造成重叠。

`prepareMeasureGrid` 只为 OSMD 创建显示副本，在各声部末尾添加不可见的全小节休止符，并继承末尾拍号与谱表数量。原始 MusicXML、语义文档、曲谱指纹、练习计划和评分数据不接收这些补位。

OSMD 2.2.1 的 `FixedMeasureWidth` 仅固定音符区域，额外的谱号和小节线宽度仍会造成行间错位。`renderMeasureGrid` 先测量必要空间，再在单次同步渲染期间调整 builder 的小节伸展阶段，让 OSMD 原生 formatter 在完整小节单元内排布音符、连线及定位锚点。临时方法在 `finally` 中恢复，并通过规则对象限定到当前实例。固定判定线的独立滚动谱面不使用此适配。

行末的预告调号/拍号不额外占一列，实际变更仍保留在下一小节。固定行列布局忽略源文件的手动换行/分页，不改变音符、时值、谱号或实际调号/拍号。

普通读谱演奏按已确认的正确目标跟随：把当前目标所在整行（含双谱表）放到视口顶部，保留少量边距；同一行内不反复移动。手动滚轮、触摸、拖动或翻页键进入浏览状态，不更改演奏进度；点击“回到当前”，或下一次弹对当前目标后恢复跟随。专注模式也保留浮动的返回按钮。时钟推进与漏音本身不触发跟随；显示层为末行增加尾部留白，使最后一行也能置顶，留白不进入乐谱或评分数据。

验证：

- `npm test` 中的 `osmdEngraving.test.ts` 检查补位数量、原有音符、不可见休止符、末尾不同拍号与多 Part 对齐。
- 开发服务打开 `/osmd-measure-grid-contract.html`，自动检查真实 OSMD 的行列数、列边界、等宽、放大与窄窗口、密集音阶、低音单谱表，以及原有音符映射和高亮。
- `/focus-score-contract.html` 的“长谱跟随”使用 32 小节只读谱例，验证正确目标、时钟推进和手动浏览的显示隔离，以及末行置顶；它不连接 MIDI 或生成评分记录。
- 升级 OSMD 版本后必须再次运行浏览器契约检查；该适配以当前固定版本 2.2.1 的 builder 接口为依据。
